Executive Summary
Green by Nature is a private equity-backed roll-up of four landscaping businesses merged in Dec 2021, now 2,300+ employees across Australia and New Zealand. It put in one ERP (SAP S/4HANA, about 2024) and is now replacing its workforce, time and attendance and payroll systems. Labour is the biggest cost, award wages rose 4.75% from Jul 2026, and many council contracts fix the year-1 price. The Senior Manager, Information, Data & AI sits under Head of Transformation Michelle Rouillon. The job is to turn the new systems into trusted contract-level profit and productivity measures that managers act on, with AI built on that foundation.

2. How the Company Became What It Is Today

Four founder-led businesses (Super Gardens 1989; Green Options 1991, Tony Herman; Skyline 1991, the Richardsons; Recreational Services NZ 1992) grew regionally. Green Options moved into SA (2016) and WA (2017) and bought Pitchcraft/STM in 2020. Fact Private equity turned it into a platform: Mercury Capital backed Green Options in Apr 2021 for a roll-up, and by Dec 2021 all four had merged under one holding company. Fact Two years later it had one brand (Oct 2023) but not one way of working: each business still ran its own systems. SAP S/4HANA was the first fix, under Julian Tan (Group IT Manager, Nov 2022 to Apr 2025). 2025 brought the operating model (divisional split, B Corp, autonomous mowing trials). 2026 is the people layer: workforce management, field service and time and attendance; payroll, HSEQ and finance transformation; and now this data role, under Head of Transformation Michelle Rouillon.

Strong Inference Today: a national operator of 2,300+ people with a single finance backbone, labour data in transition, and no one owning its data yet.

    A data assistant (questions about numbers):

    1. Prepare the data: a clean semantic model on the gold layer, with clear table and column names, descriptions and relationships. Copilot answers from the model's metadata, so this matters more than the AI settings.
    2. Fabric > your workspace > New item > Data agent. Name it and select Create.
    3. Add data source: pick the semantic model (or lakehouse or warehouse), then tick only the tables the agent should use.
    4. Write agent instructions: what the agent is for, business terms ("margin means contract revenue less direct labour and materials"), which table answers which kind of question. For lakehouse and warehouse sources, add example questions with the correct SQL.
    5. Test, then Publish. You will see it work when the test pane returns the right number and shows the query it ran.
    6. Copilot Studio > Create agent. Give it a name, description and instructions.
    7. Agents tab > Add > Connect to an external agent > Microsoft Fabric (preview), then pick your data agent. Choose End user credentials so each person only sees data they are allowed to see.
    8. Publish to Teams (and Microsoft 365 Copilot). Staff then ask questions in Teams chat, the same "meet users where they are" idea as your Webex assistant.

    A knowledge assistant (questions about documents): Copilot Studio or Agent Builder, with SharePoint sites or files as knowledge.     8. Where Azure fits

    Azure is Microsoft's cloud: rented computing power, storage, databases and AI services, paid for by use and run from Microsoft data centres, including Australia East (Sydney) and Australia Southeast (Melbourne). Fabric runs on top of it, so at GbN Azure is mostly the plumbing underneath: the Azure subscription that pays for the Fabric capacity (F SKU, billed per second, cheaper with a yearly reservation), Microsoft Entra ID (formerly Azure Active Directory) that controls who can sign in and what they can see, Azure Data Lake Storage Gen2, which OneLake shortcuts can read in place without copying, and any older Azure Data Factory or Synapse pipelines, which are still supported but which Microsoft now steers towards Fabric. The custom AI work sits in Microsoft Foundry (formerly Azure AI Foundry), where developers build agents on models such as Azure OpenAI; a Foundry agent can call a Fabric data agent as a tool, using each person's own access (preview). In short: Azure is the cloud, Fabric is the data platform, Power BI and Copilot are where people see it.
